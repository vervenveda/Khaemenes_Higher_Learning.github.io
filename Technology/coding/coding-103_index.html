Module 1 — Decomposition: Turn Big Goals into Testable Steps

Decomposition means taking “one huge thing” and turning it into small pieces you can build and test.

1 — Why Break Things Down?

Big tasks can feel blurry or overwhelming. Decomposition helps by:

  • Turning a huge goal into a clear checklist
  • Letting you build the smallest working version first
  • Making bugs easier to find because each piece is simpler

Pro tip: the smaller the step, the easier it is to test.

2 — Example: Making a Game

Big goal: “Make a platformer game.”

  • Medium tasks: Player, levels, enemies, sound, scoring
  • Tiny steps: Draw one sprite, code jump, test left/right, add one sound

Coding 103 mindset: build one tiny step → test it → then add the next step.

Module 2 — Patterns & Repetition: Spot the Loop Before You Code It

In Coding 103 we train our eyes: if something repeats, it often becomes a loop in real code.

1 — Seeing Patterns

Patterns are “rules that repeat.” Programmers use patterns to:

  • Avoid copy-pasting the same steps
  • Predict what should happen next
  • Catch bugs (because broken patterns look “off”)

State is what the program “knows” right now: score, health, level, settings, or choices.

Module 4 — Pseudocode & Flow: Plan the Logic Before the Code

Pseudocode lets you plan your program in plain language so your logic is clear and testable.

1 — What Is Pseudocode?

Pseudocode is a “plan in words” for your logic. Example:

SET total TO 0
REPEAT for each cookie on the table
    ADD 1 to total
SHOW total

Coding 103 tip: write the “happy path” first, then add edge cases later.

Module 5 — Debugging & Test Thinking: Be a Calm Bug Detective

Debugging is how coders find and fix mistakes by testing ideas step-by-step.

1 — What Is a Bug?

A bug is any mistake that makes the program behave differently than you expected.

In Coding 103, debugging usually follows this loop:

  • Reproduce the bug (make it happen on purpose)
  • Isolate where it breaks (smallest failing step)
  • Inspect state/inputs with logs or messages
  • Fix one thing, then verify with a test

2 — Bug Scenario

Goal: “When I press space, my score should go up by 1.”
Pseudocode:

SET score TO 0
WHEN space key pressed
    SET score TO score - 1
SHOW score

What is the bug?
