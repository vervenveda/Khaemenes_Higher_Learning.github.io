Module 1 — Variables & Data Types

In this module you’ll learn how programs remember information using variables and different kinds of data.

1 — Builder Mode: Memory

In 201, we start building tiny “systems” (like scoreboards, menus, trackers). Systems need memory — that’s what variables are for.

  • Variables: labeled boxes for values
  • Logic: decisions (rules)
  • Loops: repeating patterns
  • Functions: reusable commands
  • Arrays + debugging: groups + bug-hunting

2 — Variables as Labeled Boxes

A variable is like a labeled box in the computer’s memory.

  • The label (name) might be score, lives, or playerName.
  • The box holds a value that can change as the program runs.
  • Reading and updating values is how programs “keep track” of what’s happening.

Example in many languages:

  • let score = 0;
  • score = score + 10;
201 word upgrade: if a value can change, it’s sometimes called mutable (meaning “changeable”).

3 — Common Data Types

Variables can hold different types of values:

  • Number — 0, 3.14, -7
  • String (text) — "hello", "Jenny"
  • Boolean — true or false

Choosing the right type makes your code clearer and safer.

Module 2 — Logic & Conditions

Now we’ll learn how code makes decisions using if statements and true/false conditions.

1 — From Questions to Conditions

Systems run on rules. Rules start as questions:

  • “Is it raining?”
  • “Do I have enough coins to unlock this level?”

In code, these become conditions that are either true or false.

2 — Comparisons (and combining rules)

We compare values using symbols:

  • > greater than
  • < less than
  • >= greater than or equal
  • <= less than or equal
  • === exactly equal to (in many languages)

Example: if (score >= 10) means “if score is 10 or more”.

201 upgrade: combine conditions
&& means “AND” (both must be true).
|| means “OR” (at least one must be true).
! means “NOT” (flips true/false).

3 — If / Else Branches

An if statement chooses between paths:

if (lives === 0) {
  showGameOver();
} else {
  keepPlaying();
}

If the condition is true, the first block runs; otherwise the else block runs.

Module 3 — Loops & Patterns

Loops let us repeat code without copy-pasting the same lines over and over.

1 — Why Loops?

Imagine typing a line of code 100 times in a row. No thanks!

Loops let us say “repeat this block” instead:

for (let i = 0; i < 100; i++) {
  drawStar();
}

2 — Counter Loops (and a quick “break”)

A common pattern is a for loop with a counter:

  • let i = 0; — start at 0
  • i < 5; — keep going while this is true
  • i++; — increase i by 1 each time

The loop body runs once for each value of i.

201 tool: break means “stop the loop early.” Useful when you’ve found what you need.

3 — While Loops & Infinite Loops

A while loop says “keep going while this is true.”

while (energy > 0) {
  runStep();
  energy--;
}

If the condition never becomes false, the loop might run forever — an infinite loop.

Module 4 — Functions & Reuse

Functions let you name a useful block of code and reuse it whenever you like.

1 — What Are Functions?

A function is a reusable block of code that does a specific job.

  • It has a name, like drawHeart or playSound.
  • You can “call” it wherever you need that job done.

2 — Parameters & Return Values

Functions can have:

  • Parameters — inputs you pass in
  • Return values — answers the function gives back
function add(a, b) {
  return a + b;
}
let sum = add(2, 3); // sum is 5

4 — Organizing With Functions

Putting related code into functions makes your programs:

  • Easier to read
  • Easier to test
  • Easier to change later

You can think of functions as your own custom commands.

Module 5 — Arrays & Debugging

Here we learn to work with groups of values in arrays and how to hunt down bugs.

1 — Lists in Code (Arrays)

An array (or list) holds several values in order:

let colors = ["red", "green", "blue"];

Each value has a position called an index.

2 — Indexes & Access

Most languages start counting indexes at 0:

  • colors[0] → "red"
  • colors[1] → "green"
  • colors[2] → "blue"

Arrays make it easy to loop over many values in one structure.

3 — Debugging Toolkit

A bug is a mistake in code. Debugging is the process of finding and fixing bugs.

  • Read error messages carefully.
  • Use a console or log to print values.
  • Change one thing at a time.
  • Explain the code out loud (“rubber duck debugging”).
Bonus tool: comments can explain tricky code, or temporarily “turn off” a line while testing.
