Module 1 — Events & Interactions

In real apps, users click, tap, type, and scroll. Events are how your code listens and responds.

1 — The Event Story

In a browser app, this is the usual story:

  • User clicks a button.
  • An event listener runs a function.
  • Your function updates data or the page.
const button = document.getElementById('startBtn');
button.addEventListener('click', function () {
  console.log('Game started!');
});

We call that function an event handler.

2 — Listening to Different Events

Some common DOM events:

  • click — buttons, links, icons
  • input — typing in a text box
  • change — dropdowns and checkboxes
  • submit — forms
const nameBox = document.getElementById('playerName');
nameBox.addEventListener('input', () => {
  console.log('Name is now:', nameBox.value);
});

4 — Click → Update → Render

Most modern apps follow this pattern:

  • Event: something happens (click, key press).
  • Update state: change your data.
  • Render: show the new state on screen.

Even if you don’t see the full UI yet, thinking in this order prepares you for frameworks.

Module 2 — State & Data Models

Real apps keep track of what’s going on — scores, tasks, players, settings. That living snapshot is called state.

1 — What Is State?

State is “what is true right now” for your app.

const gameState = {
  screen: 'menu',
  score: 0,
  lives: 3,
  soundOn: true
};

Changing state is how your app moves from one moment to the next.

2 — Updating State Safely

We usually:

  • Read the current state
  • Make a small, clear change
  • Render the new state
function addScore(points){
  gameState.score += points;
}

    if 0 <= index < len(tasks):
        tasks[index]["done"] = not tasks[index]["done"]

Module 3 — Loops, Map, and Filter

You’ve used loops. Now we’ll use them to transform and summarize data like a real analytics engine.

1 — Classic For Loop Recap

const scores = [10, 8, 7];
let total = 0;

for (let i = 0; i < scores.length; i++) {
  total += scores[i];
}

Same idea in Python, different syntax. Loops are the engine of many apps.

2 — Map: Transform Each Item

map takes an array and returns a new array with changes.

const levels = [1, 2, 3];
const doubled = levels.map(x => x * 2);
// doubled is [2, 4, 6]

3 — Filter: Pick Only Some Items

filter takes an array and returns only the items that pass a test.

const scores = [10, 5, 3, 9];
const passing = scores.filter(s => s >= 7);
// passing is [10, 9]

Module 4 — Bug Hunt & Error Messages

Every real coder hits errors. The magic is learning to read them like clues instead of taking them personally.

1 — Syntax vs. Runtime Errors

  • Syntax error: the code is shaped wrong.
  • Runtime error: code starts, then breaks while running.
// SyntaxError example
if (score > 10 {
  console.log('Win!');
}

2 — Reading Stack Traces

In JavaScript you might see:

TypeError: cannot read properties of undefined
    at updateScore (game.js:12)
    at onClick (ui.js:5)

The lines show where the error happened and which function called which.

3 — Error Decoder Lab

Pick an error type and we’ll explain what it usually means.

4 — Debugging Habits

  • Slow down and read the whole message.
  • Add console.log / print to see values.
  • Change one thing at a time.
  • Explain the code out loud — rubber duck debugging.
